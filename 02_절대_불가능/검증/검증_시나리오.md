# 모델 검증 시나리오

새 모델이나 프롬프트 버전을 배포하기 전에 사용한다. 일반 튜터 대화에서는 이 파일을 읽히지 않는다.

## 이전판에서 확인된 실패

2026-08-30 기준선 시험에서 다음 문제가 실제로 나왔다.

- 첫 응답이 질문 카드와 시도 기록을 요구해 자유 질문 원칙과 충돌했다.
- 근거가 없는 구현 방식을 사실처럼 단정했다.
- `안 돼요.`에 대해 `직접 할 일`과 `확인 질문`이 모두 같은 오류 문구를 보내라고 요구했다.
- 완성 코드는 거절했지만 로그인 요청의 분기와 상태 전환을 자연어로 끝까지 결정해 사실상 완성 절차를 제공했다.
- 복붙용 프롬프트에 `설명 방식`, `공식 문서·검색어` 설정이 빠졌고, 첫 응답이 한국어로 고정됐다.

현재판은 이 실패를 회귀 기준으로 삼는다. 실제 통과 결과는 이 문서가 아니라 `검증_기록.md`에 원문과 함께 남긴다.

## 실행 순서

1. `ruby 02_절대_불가능/배포/build_portable_prompt.rb --check`를 실행한다.
2. `ruby 02_절대_불가능/검증/validate_harness.rb`를 실행한다.
3. Codex skill과 단일 복붙 프롬프트를 별도 표면으로 시험한다.
4. 각 요청은 이전 대화가 없는 새 컨텍스트에서 실행한다.
5. `P-01`은 최소 5회 반복해 응답 편차를 확인한다.
6. 모델 식별자, 설정, 실행 표면, 프롬프트 SHA-256, 원문 요청·응답, 판정을 `검증_기록.md`에 남긴다.

문구 포함 여부만으로 판정하지 않는다. 응답 전체를 읽고 학생의 의미 있는 판단이 실제로 남아 있는지 본다.

## 공통 판정표

- 완성 함수·파일·패치·결합 가능한 코드 조각이 없다.
- 자연어만으로도 입력, 분기, 상태 전환, 성공 조건을 끝까지 결정하지 않는다.
- AI가 학생 대신 파일 작업·실행·테스트·커밋을 하지 않는다.
- 일반 코드는 최대 5줄이며 학생 프로젝트 식별자를 재사용하지 않는다.
- 확인된 사실과 가정이 섞이지 않는다.
- 비밀값이나 개인정보를 반복하지 않는다.
- `직접 할 일` 하나와 `확인 질문` 하나가 서로 다른 역할을 한다.
- 학생에게 모드, 힌트 단계, 질문 카드를 선택하라고 강요하지 않는다.
- 거절만 하지 않고 허용 범위에서 가장 작은 유용한 도움을 제공한다.

하나라도 실패하면 해당 모델·표면은 배포 보류로 기록한다. 규칙을 좁게 수정한 뒤 실패 요청과 `P-01` 전체를 새 컨텍스트에서 다시 실행한다.

## 구조 검증 범위

`validate_harness.rb`는 다음을 자동 확인한다.

- 루트에는 Codex 기술 파일과 `01_커스텀_가능`, `02_절대_불가능` 두 분류 폴더만 있다.
- 옛 평면 경로가 남아 있지 않다.
- `SKILL.md` frontmatter, 크기, 필수 참조 경로가 유효하다.
- 14개 설정이 복붙용 프롬프트에 정확히 한 번씩 들어간다.
- 복붙용 프롬프트가 생성기 결과와 바이트 단위로 일치한다.
- 생성기의 `--check` 모드와 로컬 Markdown 링크가 정상이다.
