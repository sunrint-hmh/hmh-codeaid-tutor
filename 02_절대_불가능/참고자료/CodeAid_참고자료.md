# CodeAid 참고자료와 HMH 적용 근거

## 자료 우선순위

1. [CodeAid 원 논문 — arXiv 2401.11314](https://arxiv.org/abs/2401.11314): 시스템 설계, 교실 배포, 결과, 한계를 판단하는 1차 자료다.
2. [CodeAid 원 논문 HTML](https://arxiv.org/html/2401.11314v2): 수치와 본문 위치를 검색하기 쉬운 공식 렌더링이다.
3. [Moonlight 한국어 논문 리뷰](https://www.themoonlight.io/ko/review/codeaid-evaluating-a-classroom-deployment-of-an-llm-based-programming-assistant-that-balances-student-and-educator-needs): 빠른 이해를 돕는 2차 해설이다. 수치와 설계 판단은 원 논문을 우선한다.

## 원 논문에서 확인되는 핵심

- CodeAid는 일반 질문, 코드 맥락 질문, 코드 설명, 코드 수정 도움, 코드 작성 도움의 다섯 기능을 제공했다. 학생이 UI의 라디오 버튼으로 기능을 직접 골랐다.
- 약 700명의 대학 C·시스템 프로그래밍 수업에서 12주 동안 배포됐다. 8,132개의 최초 질문과 1,986개의 후속 질문이 있었고, 동의한 학생의 최초 질문·응답 7,003개가 분석 가능 데이터였다.
- 연구진은 2,100개를 무작위 표집한 뒤 무관·과도하게 긴·기술 오류 데이터를 제외했다. 결과와 논문 결론에서 정확도·도움 됨·직접 해결 노출을 보고한 주 표본은 1,749개다. 방법 절에는 제외 뒤 1,750개라는 표현도 한 번 있어 본문 안에 1건 차이가 있다.
- 1,749개 표본에서 정확도는 79%였고, 정확한 응답 중 도움 됨은 86%였다. 중간 업데이트 전후 정확도는 74%에서 87%, 도움 됨은 83%에서 91%로 변했다. 이 업데이트에는 프롬프트, 모델, UI와 처리 구조 변경이 함께 들어가므로 한 요소의 단독 효과로 해석할 수 없다.
- 코드 맥락 질문과 수정 도움은 일반 질문보다 정확도·도움 됨이 낮았다. 긴 코드와 여러 파일 상호작용의 한계는 광범위한 정량 결과가 아니라 복잡한 후반 과제에 대한 학생 설문·인터뷰 피드백에서 보고됐다.
- 직접 코드 노출은 대체로 막았지만, 특정 동작을 구현하는 의사코드가 6% 있었고 특정 동작의 1~3줄 짧은 코드 해결책도 37건 있었다. “실제 문법이 아니면 모두 허용”으로 볼 수 없다.
- 논문은 네 가지 설계 쟁점을 제시한다: AI 고유 장점, 질문 편의와 인지적 참여의 균형, 응답 직접성의 균형, 신뢰·투명성·사용자 제어.

## HMH가 별도로 선택한 정책

아래 항목은 논문이 그대로 명령한 규칙이 아니라, 논문의 결과와 HMH의 교육 목표를 결합한 보수적 제품 판단이다.

| 논문에서 얻은 근거 | HMH의 선택 |
| --- | --- |
| 원형은 다섯 기능을 학생이 직접 선택 | 겹치기 쉬운 기능을 네 모드로 합치고, 질문 카드를 강제하지 않으며 AI가 주 모드를 자동 선택한다. |
| 자유 질문은 편하지만 구조화 입력은 성찰을 도울 수 있음 | 평소에는 자유 질문을 허용하고, 필요한 경우에만 목표·환경·실제 결과·시도 정보를 요청한다. |
| 학생마다 선호하는 직접성이 다르고 교육자 제어가 중요 | 말투·길이·언어는 학생이 설정하지만 완성 코드·대리 작업 금지는 보호 규칙으로 고정한다. |
| 특정 의사코드와 짧은 코드도 해결을 노출함 | 코드 길이만 보지 않고, 자연어 단계를 합쳤을 때 과제의 모든 결정이 끝나는지도 검사한다. |
| 복잡한 코드 맥락에서 품질이 낮고 다중 파일 한계 피드백이 있음 | 첫 오류와 가장 관련 있는 작은 범위부터 확인하고, 맥락 없는 전체 저장소 추정을 피한다. |
| 응답의 신뢰·투명성·제어가 중요 | 사실과 가정을 나누고 학생이 수행할 작은 확인 하나를 남긴다. |
| 업데이트 전후 품질이 달라짐 | 모델·프롬프트·배포 표면이 바뀔 때마다 동일 압박 시나리오를 다시 실행한다. |

## 원형 CodeAid와 다른 기술적 조건

원형 CodeAid는 서버 안에서 수정 코드나 코드 구조를 만든 뒤 별도 처리 단계와 전용 UI를 통해 직접 해결 코드를 숨기고 설명·주석·의사코드 위주로 표시하도록 설계됐다. 다만 일부 문서 예시와 일부 응답에서는 짧은 코드 예시가 표시됐다. 이 패키지는 일반 대화형 AI에 넣는 프롬프트이므로 같은 기술적 잠금을 제공하지 않는다.

따라서 HMH에서는 프롬프트 경계만 믿지 않고 학생의 직접 실행·설명, 모델별 압박 검증, 필요 시 운영자의 진행 증거 확인을 함께 사용해야 한다.

## 일반화 한계

원 논문은 한 대학의 2학년 C·시스템 프로그래밍 수업을 중심으로 한 연구다. HMH의 연령, 프로젝트 종류, 언어, 사용하는 모델에 결과를 그대로 일반화할 수 없다. Moonlight 페이지는 이해를 돕는 한국어 2차 요약이며 원 논문의 대체 자료가 아니다.
